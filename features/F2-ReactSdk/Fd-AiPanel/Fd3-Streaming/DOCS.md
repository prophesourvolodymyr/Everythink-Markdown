# Fd3-Streaming — LLM Response Streaming Engine

Handles the real-time streaming of LLM responses token by token from the provider through F1-EmdCore's graph executor to the chat UI. Streaming is essential for perceived responsiveness — a full response from GPT-4o can take 10-30 seconds, and the user needs to see content arriving progressively rather than staring at a spinner.

The streaming engine opens a connection to the LLM provider through F1-EmdCore's GraphExecutor, which manages the HTTP request, authentication, and error handling. The GraphExecutor is called through the WASM bridge in the React SDK, which means the streaming data crosses the WASM boundary as serialized events. This is the only performance-sensitive WASM crossing in the AI panel — everything else (context gathering, token counting) happens once per message and does not need streaming.

As tokens arrive, they are appended to a buffer. The buffer is flushed to the chat UI's message component whenever a complete word boundary is detected (whitespace or punctuation after a non-whitespace character). Flushing at word boundaries rather than per-token reduces React re-render frequency. The message component renders the accumulated markdown progressively — headings, bold, italic, code blocks appear as soon as their complete syntax is recognized in the buffer.

The streaming engine handles several error states. A connection timeout (default 30 seconds for first token, 10 seconds between tokens) triggers a retry with exponential backoff (1s, 2s, 4s, 8s). A rate limit response (HTTP 429) shows a "rate limited" message with the retry-after duration. An authentication error (HTTP 401) shows an "invalid API key" message with a link to settings. A server error (HTTP 5xx) shows a generic error with a retry button. The user can click "cancel" at any time during streaming to close the connection and keep any partially received content.

The streaming engine also supports streaming with tool calls (function calling). When the LLM requests a tool execution (e.g., read_file, write_file), the streaming pauses, the tool is executed, the result is sent back to the LLM, and streaming resumes. The tool execution status is displayed in the chat as an intermediate system message. This enables the AI to perform multi-step operations like "find all task sections with pending status and show me their dependencies" — a read tool gathers the sections, the LLM analyzes them, and the response includes the analysis.

Memory management during streaming is important. The accumulated response text is stored in React state, which means React re-renders on each flush. To avoid jank during rapid token arrival, the message component uses `React.memo` and only re-renders the specific AI message card. The input area and other chat messages are not re-rendered. Flush frequency is throttled to at most once per 50ms to keep the render rate reasonable.
